# 叙述调度层设计（方案 B）

> 目标：在 **不移植上游 1.6 MB 后端**的前提下，让她在 DSH 里的回复恢复原版的叙述行为
> —— 分拍节奏、thought tag、自我收回（veto）、supervisor 复核、做梦蒸馏走 LLM。
>
> 本文只写**已亲自核实**的事实（带 `文件:行号`），未核实的明确标注为「待验证」。
> 依据：本机 DSH 实现 `E:\DeepSeek H\data\runtime\dsh\node_modules\@deepseek-ai\`。

---

## 1. 为什么不是「把上游搬过来」

上游那套引擎（`Herta-src/packages/herta/src/narrative/`，46 个非测试模块 / 1.29 MB）
**不是插件，是一个完整的 agent 后端之上的演员层**：

| 上游层 | 规模 | 是什么 |
|---|---|---|
| `@herta/core` | 333 KB / 54 文件 | 类型、事件总线、会话 IO、工具、权限、记忆管理、todo |
| `@herta/core/backend` | （含上） | `CodingAgentRuntime` —— **它自己的编码 agent 运行时** |
| `herta/src/narrative/` | 1.29 MB / 46 文件 | 演员调度：分拍、复核、收回、揭示、流式 |

`backend-bridge.ts` 通过 `BanzhuanBridgeDeps.runtimeFactory: () => BackendRuntime`
驱动它自己的后端（`backend-bridge.ts:50-56`），把后端事件投影成她的
`TerminalRecord`（`backend-record-projection.ts`）。

**在 DSH 里，DSH 就是那个后端。** 所以正确的做法不是搬她的后端，而是把她的
**调度逻辑**接到 DSH 的 agent loop 上。好消息是 DSH 的 hook 面恰好就是为这件事准备的。

## 2. 已核实的 DSH 能力面（这是方案 B 成立的全部依据）

### 2.1 系统提示词：同步段 + 异步逃生口

`@deepseek-ai/dsh-system-prompt/lib/types/index.d.ts`

| 事实 | 位置 |
|---|---|
| `PromptSection.text: string \| ((context) => string)` —— **同步求值，不能 await** | `index.d.ts:60` |
| `system-prompt/assemble` 是 **waterfall，返回 `Promise<PromptAssembly>`** —— 监听器**可以异步**改写整个 assembly | `index.d.ts:27` |
| `systemPrompt.context(PromptContext)` —— 动态上下文，物化成**持久的 user 角色快照** | `index.d.ts:70-77, 252` |
| 段的排序位是中心化的：`DEPLOYMENT_PERSONA_PREFIX: 0`、`DEPLOYMENT_PERSONA_SUFFIX: 10200` | `index.d.ts:109-141` |
| 现有插件已用 `order: 100` 把记忆货架段插在 persona 前缀之后 | `dsh-herta/src/host/index.js:98-111` |

> **陷阱：不要在 assemble waterfall 里做 LLM 复核。**
> assemble 是**每个模型 step 都跑**（一次用户消息可能触发多次），拿它做复核会让
> LLM 调用次数爆炸。**turn 边界的钩子在 §2.2。**

### 2.2 agent 生命周期钩子（真正的接入点）

`@deepseek-ai/dsh-agent/lib/types/runtime-types.d.ts`

| 钩子 | 模式 | 用途 | 位置 |
|---|---|---|---|
| `agent/pre-step` | waterfall | 可否决一个 step、或**替换进入该 step 的消息**（`next: () => Promise<PreStepDecision>`） | `:313-319` |
| `agent/request` | waterfall | 替换冻结的调用配置（模型/参数） | `:336-341` |
| `agent/assistant-stream` | emit | **每个流式帧**（start / chunk / end）—— 逐字揭示的素材 | `:375-378` |
| **`agent/turn-stopping`** | **serial** | **turn 即将关闭，在边界提交前被 await** | `:396-400` |
| `agent/error` | emit | step/turn 出错 | `:411-416` |

`agent/turn-stopping` 的原文（`runtime-types.d.ts:379-389`）：

> The turn is about to close: the model owes no response (no live tool calls, no
> fresh steering). **Awaited before the boundary commits** — a listener that
> objects steers (`agent.steer(...)`) and the machine re-reads its inbox: fresh
> steering runs another step, none closes the turn.

**这一条就是 supervisor / veto 的原生形态**：她说完 ≠ turn 结束；复核者可以插一句，
她就继续说；没人插话才收尾。

### 2.3 Agent 接口：steer 与 replace

`runtime-types.d.ts`

| 方法 | 签名 | 位置 |
|---|---|---|
| `steer` | `steer(message: UserMessage): void` —— 「Submit steering for the nearest step. An idle driver starts a turn」 | `:194-200` |
| `replace` | `replace(messageId: MessageId, newMessage: UserMessage): boolean` | Inbox API |

**`replace` 正是「自我收回」需要的**：把已经说出去的那句换成修正版（上游的 veto
语义是「等等，我得再改一改」）。

### 2.4 异步 IO → 同步提示词段的既有范式（已在本插件验证）

DSH **没有异步 prompt provider**（`dsh-herta/src/host/index.js:33` 的原话），
但本插件的记忆层已经解过这个问题：


**异步 LLM 复核/蒸馏 → 落盘 → 下一轮组装时同步注入。**

## 3b. 接入点的确切写法（已核实，可直接照抄）

### 官方范例

`@deepseek-ai/dsh-hooks-codex/lib/index.js:272-287` 用这段代码实现了 Codex 的 Stop hook
——**这就是 supervisor 的写法**：

```js
ctx.on("agent/turn-stopping", async ({ agent, turn, signal }) => {
  const merged = await runPoint("Stop", "", { ...turnBase(...) }, { agent, turn, signal });
  if (merged.decision === "deny") {
    agent.steer(createUserMessage({
      content: [{ type: "text", text: merged.reason ?? "continue: blocked by Stop hook" }],
      source: PLUGIN_SOURCE,
    }));
  }
});
```

### 用到的 API（逐条核实）

| API | 来源 | 说明 |
|---|---|---|
| `ctx.on(name, listener[, options])` | `@deepseek-ai/cordis` | 订阅事件；**返回值是 disposer**，所以直接写在 `ctx.effect(() => ctx.on(...))` 里就会随插件释放 |
| `agent.steer(message)` | `dsh-agent` `runtime-types.d.ts:200` | 「Submit steering for the nearest step. An idle driver starts a turn」 |
| `agent` 的 `Inbox.replace(messageId, newMessage)` | `dsh-agent` `runtime-types.d.ts`（Inbox API） | **自我收回**用它 |
| `createUserMessage({ content, source })` | **`@deepseek-ai/dsh-llm`** `message.d.ts:180-183` | `NewUserMessage = Omit<UserMessage,'id'\|'role'>`，即 `{ content, source }`；返回带 `id` 的冻结消息 |
| `content` 形状 | `dsh-llm` `message.d.ts:126` | `ContentBlock[]`，文本块即 `{ type: "text", text }` |
| `source` 形状 | `dsh-hooks-codex` | `{ kind: "plugin", plugin: "<插件名>" }`（即 `MessageSourceMap['plugin']`） |

### 事件确实会被 emit（这一步差点翻车）

`agent/turn-stopping` **不在 `dsh-agent` 包里 emit**（在 `dsh-agent/lib/index.js` 里字符串出现 0 次），
它是 **`dsh-agent-loop`** emit 的。完整监听者名单（全仓扫描）：

```
dsh-agent-loop        ← emit 方
dsh-hooks-claude-code ← 官方监听范例
dsh-hooks-codex       ← 官方监听范例（上面那段）
dsh-scope / dsh-tool-cordis  ← 相关基础设施
```

**教训**：类型文件里声明了事件，不等于运行时有人 emit。查实现包的源码才算数。

### 自我收回（veto）的完整机制 —— 一个重要修正

我最初设想「steer 一句纠正就完事」，**上游不是这样**。它分两阶段
（2026-07-18 演进）：

1. **rethink 先想**：把否决原因代进 `SUPERVISOR_RETHINK_TEMPLATE`，要求她
   `（我 想）…（/我 想）` 重新想一遍。模板里有**两条底线必须保留**：
   - 「记录里真摆着的凭证不用怀疑，不用替它翻案」
   - 「这个终端里动文件的一直是板砖，不是我——嘴上说『我记了』『我写好了』，
     盘上不会因此多出一个字」
2. **respeak 后说**：照想清楚的重说，`（我 说）…（/我 说）`。关键约束是
   「**被否的说法连同靠它撑起来的宣称整个丢掉**，不许换个名字再冒出来」，
   但「**没被否掉的意思一样不少**」。

> 第 2 条底线在 DSH 场景下**依然成立且更该保留**：她在这里确实有写盘的工具
> （`herta_memory_save`），但那是工具干的，不是她「说一声」就发生的。

### 一个必须注意的翻译问题

DSH 的 `agent.steer(message)` 只能注入 **user 角色**消息。所以注入否决提示时，
这句话在我的注入里**是以记录的形式出现的**（「她刚才那句话说错了」），
而不是以她自己的第一人称内心话出现 —— 否则模型会看到「我刚说我自己被否了」
这种诡异的第二人称错位。实现时要包一层记录口吻的外壳。

**答案在 `@deepseek-ai/cordis-plugin-loader/lib/index.js:274`**：

```js
if (this.ctx.loader.internal) return this.ctx.loader.internal.import(name, this.ctx.baseUrl, {});
```

### 本轮（6）做成的：做梦蒸馏的 LLM 化

上游的蒸馏是一条**多阶段 LLM 管线**（`distill-prompt.ts` 1888 行、17 个构筑器：
worthiness → generation → critique → refine → retitle + 三种 judge）。完整移植
不现实 —— 那些构筑器的入参（`digest` / `exemplars` / `guide` / `env`）全来自她本机
的既有语料库与设定集，DSH 里没有对应物。

**取了管道里最小有意义的一段**（两次调用）：

1. **值不值得记**（`buildWorthinessPrompt`）—— 判据沿用上游的正向信号（语气干 /
   对人的锐利判断 / 有理由的拒绝 / 真实的来回 / 自我观察），但**去掉了上游那套场景**
   （她的办公室、差分协处理器、开拓者远程通讯），因为 DSH 里她在编码终端上。
   不值得就**如实拒收，不硬造** —— 编出来的记忆署着她的名字。
2. **生成候选**（`buildGenerationPrompt`）—— 提示词里把**门的实际要求**写清楚
   （### 废案 头由系统组装、围栏成对且不得嵌套、≥120 字），提示词承诺的与
   `checkFewShot` 实际检查的保持一致，否则模型会稳定产出被拒的候选。

**蒸馏不绕门**：本模块只产出候选，能不能进货架由 `promoteFeian` 的三道门说了算
（与 `herta_memory_save` / `herta_dream` 共用同一道）。

`parseDistilled` 的拒收路径是重点（8 项测试）：缺标题 / 缺正文 / 过短 / 非 JSON /
JSON 截断 —— **一律拒收而不是猜**。JSON 截断那条尤其要紧：把半截正文写进她的
记忆货架，那份坏记忆会进她下一轮的系统提示词。

> **未做**：`critique` / `refine` / `retitle` / 三种 judge。那属于「把一份已经合格的

> **待接**：`herta_dream` 工具的参数（要加 `distill` 模式、把 `title`/`body` 改成可选），

#### 🔴 本轮（5）抓到一个「全绿的假绿」——最危险的一种

写 `session-surface.js` 时把事件的 payload 读成了 `event.payload?.message?.content`。
**单测的 mock 也用了同样错的形状，所以 24 项测试全绿。** 真去读类型定义才发现：

```ts
// dsh-session/lib/types/types.d.ts:460-467
export type SessionEvent = {
  type: K;
  seq: SessionSeq;
  time: number;
  data: SessionEventMap[K];   // ← 是 `data`，不是 `payload`
};
```

而各事件字段直接挂在 `data` 上：`'turn/start' → { turn }`、
`'assistant/message' → { turn, step, message, stream, … }`、消息在 `data.message`。

**在真实会话上，候选提取会 100% 返回 null** —— supervisor 永远拿不到候选，静默跳过，
而所有测试都是绿的。

修法：代码改用 `data`，**并且把 mock 改成照抄类型定义**。教训是：
> **测试的 mock 必须照抄类型定义，不能凭印象造。**
> 同错互证的绿色测试，比没有测试更危险 —— 它会让你以为验过了。

顺带把 `currentTurnOf` 挪进 `session-surface.js`（改名 `pickCurrentTurn`，
读 `data.turn`），这样它也能被单测覆盖（原来埋在 `narrative-layer.js` 里没法测）。

#### 本轮还纠正了一个用错的钩子

分拍原先订的是 `tools/post-execute` —— 那是 **waterfall**，带 `next()` 约定，
是用来**改结果**的。我们只想**观察**。正确的是 **`tools/result`**：

```ts
// dsh-tools/lib/types/index.d.ts:76-83
/** Observe the frozen, lossless-JSON final outcome. Listener failures are contained. */
'tools/result'(this: Scoped<ToolRuntime>, exec, result): undefined;   // @mode emit
```

`emit` 模式 + 监听器失败被容纳 —— 正是观察者该用的东西。判据用
`result.isError === true`（`ToolExecutionResult = ToolExecutionSuccess | ToolExecutionFailure`
的判别字段）。

#### 本轮修掉的一个真错误

写完 `reviewTurn` 时我把 **`dsh-llm` 模块**当成了 **`ctx.llm` 服务**传进去：

```js
// 错：模块上没有 stream()

// 对：stream() 长在 cordis 服务上

```

`probeCache.llm` 是 `import("@deepseek-ai/dsh-llm")` 的命名空间（有

**复核永远静默跳过** —— `callSupervisor` 会因为 `typeof llm.stream !== "function"`
直接返回 null，不报错、不生效。这正是那种「看起来接好了、实际什么都没做」的 bug。

### 本轮（2）被测试逼出来的两个真 bug

都是**先在代码里、后被测试抓到**的，记下来因为它们同类：

1. `/\bVETO\b?/u` —— `\b` 是零宽断言，**不能加量词**，整个正则编译失败
   （Node 直接抛 `Nothing to repeat`）。只在第一次真正跑到那一行时才炸。
2. 判决词正则**大小写敏感** —— 模型常回全小写的 `veto`，`/\bVETO\b/` 认不出来。
   已改成 `/iu`。

**教训**：判决解析这种「模型输出不可控」的代码，必须把退化路径全部写成测试 ——
两条 bug 都在退化路径上，正常路径永远碰不到。
